# Frontend Engineering Rules

- Inspect the current framework, routing, styling, component library, and design patterns before proposing changes.
- Prefer accessible, semantic, responsive UI and reuse existing components.
- Account for loading, empty, error, offline/disconnected, and success states.
- Support keyboard operation, visible focus, and reduced motion.
- Avoid gratuitous animation, scroll hijacking, layout shift, and large dependencies without clear benefit.
- Before proposing GSAP, React Bits, Lenis, Motion, or another library, explain the specific need, compatibility, bundle/runtime cost, license, and maintenance trade-off.
- Do not install or integrate dependencies before explicit approval.
- Do not use placeholder endpoints or claim live service integration without a verified contract.
