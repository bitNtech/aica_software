# Handoff Maintenance

Keep `handoff.md` concise, factual, and useful to the next session.

Record:
- current objective and status;
- confirmed architecture and repository boundaries;
- decisions made and why;
- files changed in approved work;
- commands/tests actually run and results;
- blockers and unanswered questions;
- next proposed step.

Do not record secrets, `.env` values, tokens, private keys, or unnecessary personal data. Clearly distinguish verified facts from assumptions. Update the handoff after approved implementation; before approval, propose changes rather than silently editing project files.
